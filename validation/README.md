# Validation

This folder holds **validation reports** for canonical output.

## Relationship between semantic and dashboard canonical

**File:** `semantic_dashboard_relationship.md`

Explains how the two canonicals relate: dashboard field references `(datasource_id, field_id)` correspond to semantic `(Field.source_table, Field.name)`. Dashboard does not reference semantic by file; the link is by convention (same table and field names from the same report).

## Canonical validation report

**File:** `canonical_validation_report.md`

Generated when you run the canonical output validation test. It lists each report under `canonical_output/`, with:

- **Semantic** – whether `metadata_model.json` is valid (MetadataModel schema)
- **Dashboard** – whether `dashboard_metadata.json` is valid (DashboardMetadata schema)

## Semantic–dashboard cross-reference report

**File:** `semantic_dashboard_crossref_report.md`

Generated by the same test run. For each report, checks that every dashboard field reference (in visualizations’ data_mappings and filter_components) exists in the semantic model as a field with matching `source_table` and `name`. Fails if any reference does not resolve.

### How to generate the reports

From the repo root:

```bash
uv run pytest tests/validation/ -v
```

This runs two tests:

1. **Schema validation** – Parses each `metadata_model.json` and `dashboard_metadata.json`; writes `canonical_validation_report.md`. Fails if any file is invalid.
2. **Semantic–dashboard cross-ref** – Ensures every `(datasource_id, field_id)` in the dashboard exists in the semantic model; writes `semantic_dashboard_crossref_report.md`. Fails if any reference does not resolve.

### Overriding canonical output path

Set `CANONICAL_OUTPUT_DIR` to an absolute path to validate a different directory:

```bash
set CANONICAL_OUTPUT_DIR=C:\path\to\canonical_output
uv run pytest tests/validation/ -v
```

(Linux/mac: `export CANONICAL_OUTPUT_DIR=/path/to/canonical_output`)
